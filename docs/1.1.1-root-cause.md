# 1.1.1 root cause

OpenCart 3 can render a non-instance extension module from `Design → Layouts` by calling its controller without a module settings array. ProBG Blog previously used a non-empty `$setting` value as the only signal that the controller was being used as a layout block. When `$setting` was empty on `common/home`, the controller incorrectly executed the full blog page renderer. That renderer loads layout positions again and can invoke ProBG Blog recursively.

The fix uses the current request route and blog IDs to distinguish direct blog page requests from layout module calls, and adds a request-level recursion guard for layouts shared with the blog section.
