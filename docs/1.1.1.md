# ProBG Blog 1.1.1

## Български

### Поправка на layout/menu рекурсията

Версия 1.1.1 коригира критичен storefront проблем при добавяне на ProBG Blog като модул в **Design → Layouts**, включително на началната страница.

OpenCart 3 може да извика неинстанциран модул от layout без `$setting` масив. Досегашната логика приемаше, че липсата на `$setting` означава директно отваряне на `/blog`, и стартираше пълния `listing()` renderer. Той от своя страна зарежда `content_top`, `content_bottom`, колоните и layout модулите отново. Ако ProBG Blog присъства в същия layout, това създава рекурсивно зареждане и страницата не завършва.

В 1.1.1 controller логиката различава директна блог страница от layout извикване чрез текущия OpenCart route и blog параметрите. На начална, продуктова, категорийна и други страници се рендерира само избраният layout output — **Меню** или **Последни статии**.

Добавена е и request-level защита `probg_blog_page_rendering`, която предотвратява повторно пълно рендериране, ако ProBG Blog бъде поставен в layout, използван от самата блог секция.

### След обновяване

1. Качете версия 1.1.1.
2. Отворете **Extensions → Modifications**.
3. Натиснете **Refresh**.
4. Изчистете theme/cache при нужда.
5. Добавете ProBG Blog към Home layout и изберете желаното **Layout output**.

## English

### Layout/menu recursion fix

Version 1.1.1 fixes a critical storefront issue when ProBG Blog is assigned as a module in **Design → Layouts**, including the home page.

OpenCart 3 can invoke a non-instance module from a layout without passing a `$setting` array. The previous controller logic treated the missing `$setting` value as a direct `/blog` page request and executed the full `listing()` renderer. That renderer loads `content_top`, `content_bottom`, columns and layout modules again. If ProBG Blog is present in the same layout, this causes recursive rendering and the page never completes.

Version 1.1.1 distinguishes a direct blog page request from a layout module call using the current OpenCart route and blog parameters. On home, product, category and other storefront routes it renders only the configured layout output — **Menu** or **Latest articles**.

A request-level `probg_blog_page_rendering` guard also prevents recursive full-page rendering when ProBG Blog is assigned to a layout used by the blog section itself.

### After upgrading

1. Upload version 1.1.1.
2. Open **Extensions → Modifications**.
3. Click **Refresh**.
4. Clear theme/cache if required.
5. Assign ProBG Blog to the Home layout and select the required **Layout output**.
